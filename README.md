# GoalBudget

MacBook などの「欲しい物」を買うための、**1人専用の家計簿・貯金目標管理アプリ**です。
iPhone 17 Pro Max のホーム画面に追加して、普通のアプリのように毎日使うことを前提に作られています。

- 今いくら貯まっているか / あといくら必要か
- 目標日までに間に合うか（順調・少し遅れ・遅れ気味）
- 毎月・毎週いくら貯めればいいか
- 今月なにに使っているか
- 今のペースなら、いつ買えるか

をひと目で確認できます。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 目標 | 買いたい物・目標金額・現在の貯金額・貯金開始日・購入目標日（アクティブな目標は1件） |
| 高速入力 | 起動後 1 タップで支出入力。金額 → カテゴリ → 日付（今日が初期値）→ メモ（任意）。数字キーパッドが自動で開きます |
| 取引 | 収入・支出の追加 / 編集 / 削除（削除は確認あり、直後の「取り消す」も可能） |
| 定期収入・固定支出 | 毎月 / 毎週 / 毎年、開始日・終了日・有効/無効。日付が来ると自動記録（二重記録なし） |
| ダッシュボード | 現在額・達成率・残額・残り日数・必要な貯金（1日・1週・1か月）・今月の収支・順調度と理由 |
| 収支の目安 | プラン画面の表で、定期収入・固定支出をルールごとに日割り・週割り（1日・1週・1か月）。その他の収支の平均、収支、必要な貯金、目標との差（余裕/不足）まで一覧 |
| 予測 | 定期収支 + 直近 3 か月（最大 90 日）の平均で、予測達成日と目標日の予測額を計算。記録が 30 日分未満のときは「支出データがまだ十分ありません」と表示し、架空の数字は出しません |
| グラフ | 貯金の推移（実績・予測・理想ペース・目標ライン・今日の線・達成見込み日、「目標日まで / これまで」切り替え）、月別の収支（最新月の値と表つき）、カテゴリ別の支出内訳 |
| 履歴 | 月・収入/支出・カテゴリで絞り込み |
| バックアップ | JSON の書き出し（iOS の共有シート →「ファイル」に保存）と復元（「ファイル」から選択）、CSV 書き出し |
| 表示 | ダークモード（自動 / ライト / ダーク）、Dynamic Island・ホームインジケータ対応 |
| PWA | ホーム画面に追加して全画面で起動、オフラインでも起動 |

## iPhone での使い方

1. Safari でアプリの URL（`https://kangchenjunga-8586.github.io/-web-/`）を開く
2. 画面下の **共有ボタン** →「**ホーム画面に追加**」
3. ホーム画面の GoalBudget アイコンから起動し、目標を入力して「はじめる」
4. 支出はホームの「− 支出」または下中央の「＋」から記録
5. バイト代やサブスクは「設定 → 定期収入 / 固定支出」に登録すると自動で記録されます
6. ときどき「設定 → バックアップを書き出す」で「ファイル」アプリ（iCloud Drive など）に保存しておくと安心です

機種変更やアプリの再追加のときは、最初の画面の「バックアップから復元する」でファイルを選べば元通りになります。

## データの保存とプライバシー

- 家計データは **この iPhone の中（IndexedDB）だけ** に保存されます。サーバーはありません
- 外部への送信・アカウント・広告・アクセス解析・トラッキングは一切ありません
- アプリの更新でデータが消えることはありません（データベースは移行方式で更新されます）
- ブラウザにストレージ保護（`navigator.storage.persist()`）を要求しています
- iPhone 本体からアプリ（ホーム画面のアイコン）を削除すると、データも削除されます。事前にバックアップを書き出してください

## 技術構成

- React 19 + TypeScript 6 + Vite 8 + Tailwind CSS 4
- Dexie 4（IndexedDB）+ dexie-react-hooks（ライブクエリ）
- Recharts 3（グラフは遅延読み込み）
- vite-plugin-pwa（Workbox、オフラインシェル、更新はユーザーの操作で適用）
- Vitest + React Testing Library + fake-indexeddb / Playwright（440 × 956 の iPhone 17 Pro Max ビューポート）

```
src/
  domain/    計算・日付・金額・定期生成・バックアップ検証・CSV（UI 非依存の純粋関数 + テスト）
  storage/   IndexedDB（Dexie）スキーマとリポジトリ（UI はここ経由でのみ保存）
  ui/        画面・シート・コンポーネント・グラフ・フック
e2e/         Playwright のシナリオ・iPhone レイアウト検証・PWA 検証
```

設計上のルール（金額は整数の円、日付は Asia/Tokyo の暦日文字列、定期取引は決定的 ID で冪等 など）は [CLAUDE.md](CLAUDE.md) にまとめています。

## テスト

すべて GitHub Actions（クラウド）で自動実行されます。

- Lint（ESLint）/ 型チェック（tsc）
- ユニット・結合テスト（Vitest）: 計算、定期取引の重複防止、予測、バックアップ検証、IndexedDB の保存・復元など
- E2E（Playwright, 440 × 956）: 初回設定、支出/収入の追加、定期収入/固定支出の自動反映、編集/削除、バックアップの書き出し→全削除→復元、再読み込み後のデータ保持、Safe Area・キーボード・タッチ領域・横向き・文字拡大・ダークモード、PWA のオフライン起動
- E2E は Chromium と WebKit（Safari のエンジン）の両方で実行

開発用コマンド（Claude Code のクラウド環境で使用）:

```bash
npm ci
npm run lint && npm run typecheck && npm test
npm run build && npm run e2e
```

## デプロイ

`main` ブランチに変更が入ると、GitHub Actions が **テスト → ビルド → GitHub Pages へ公開** を自動で行います（`.github/workflows/ci.yml`）。
公開 URL: `https://kangchenjunga-8586.github.io/-web-/`

公開は完全に自動です（マージから約 6 分）。GitHub の Actions 画面で「Run workflow」を押す必要はありません。`main` で実行中の公開作業は、あとから別の実行が起動されても取り消されません。

### 最初の 1 回だけ必要な設定（iPhone の Safari で github.com を開いて操作）

1. リポジトリの **Settings → Pages → Build and deployment → Source** を「**GitHub Actions**」にする
2. 無料プランで private リポジトリの場合は GitHub Pages が使えないため、**Settings → General → Danger Zone → Change repository visibility** で Public にする（公開されるのはアプリのコードだけで、家計データは含まれません）

公開後のアプリ本体は誰でも開けますが、データは各端末の中にしか保存されないため、他の人にあなたの家計が見えることはありません。
